# 経済シミュレーション

## 1. 収益モデル

```
収益 = 旅客収入 + 貨物収入 + 不動産収入 + 流通収入
     - 維持費 - 減価償却
```

### 旅客収入
```
旅客収入 = Σ(需要 × シェア × 運賃)
需要 = (from.Demand + to.Demand) / 2
シェア = 自社路線の競争力 / 全路線の競争力
```

### 貨物収入
- 戦前〜1970年代までは主要
- モータリゼーションで衰退
- 貨物専用線は1970-80年代に整理

### 不動産収入（阪急モデル）
- 百貨店・住宅・遊園地からの収入
- 沿線開発で地価上昇 → 需要増（`City.Developed`、需要 1.0〜2.0 倍）
- 阪急は+50%補正
- Phase 1-8-2.5 で開発度の需要効果を最大 2.0 倍に調整（第 2 節「開発度の効果」参照）

### 流通収入
- スーパー・コンビニ・駅ナカ
- 現代になるほど重要

## 2. 需要モデル

Phase 1-7.7 で人口に線形比例するモデルからべき乗則へ変更し、
Phase 1-7.8 で開発度（Developed）の効果を導入、Phase 1-8-2.5 で
開発効果を 1.0〜2.0 倍に調整した。

```go
const DevelopedDemandFactor = 1.0

func (g *Game) Demand(city *City) int {
    // べき乗則: 人口の 0.6 乗（交通工学の経験則 0.5〜0.7 の中間値）
    base := math.Pow(float64(city.Population), DemandExponent) /
        math.Pow(float64(DemandBase), DemandExponent)
    // 開発度による需要倍率: Developed=0.0→1.0倍、0.5→1.5倍、1.0→2.0倍
    developed := 1.0 + city.Developed*DevelopedDemandFactor
    seasonal := g.SeasonalFactor()      // 季節変動
    return int(base * developed * seasonal)
}
```

`DemandExponent = 0.6`、`DemandBase = 1000`、`DevelopedDemandFactor = 1.0`。

### 人口のべき乗則（Phase 1-7.7）

| 都市 | 人口 | 旧需要（線形） | 新需要（べき乗則・Developed=0） |
|------|------|----------------|--------------------|
| 宝塚 | 3 万 | 30 | 約 7 |
| 梅田 | 12 万 | 120 | 約 16 |
| 神戸 | 40 万 | 400 | 約 33 |

線形モデルでは人口 3 万→40 万で需要が 13 倍になったが、べき乗則では
約 4.7 倍に圧縮される。大都市の需要が過大にならず、神戸〜梅田のような
大都市間路線の営業係数を現実的な範囲に収められる。

### 開発効果

DevelopedDemandFactor = 1.0（Phase 1-8-2.5）

- 開発度 0.0: 需要 1.0倍
- 開発度 0.5: 需要 1.5倍
- 開発度 1.0: 需要 2.0倍

Phase 1-7.8 で導入した開発度の係数を、Phase 1-8-2.5 で 4.0 → 1.0 に
引き下げた。需要倍率は Developed=0.0 で 1.0 倍、0.5 で 1.5 倍、
1.0 で 2.0 倍となる。

| Developed | 需要倍率 | 意味 |
|-----------|---------|------|
| 0.0 | 1.0 倍 | 未開発 |
| 0.5 | 1.5 倍 | 住宅地・遊園地を整備 |
| 1.0 | 2.0 倍 | 百貨店・大規模沿線開発 |

**根拠:** 史実の阪急（小林一三モデル）は、宝塚新温泉・宝塚少女歌劇・
沿線住宅地・阪急百貨店といった沿線開発によって需要を **2 倍**に伸ばした。
小林一三の「乗客を自ら作り出す」思想を表現する。Phase 1-7.8 の係数 4.0
（最大 5.0 倍）では開発が強すぎ、プレイテスト（1931 年）で営業係数が
史実の 1/4（14.3〜25.0）まで低下し、24 年で資金が 62 倍に増えた。
Phase 1-8-2.5 で係数を 1.0 とし、需要倍率を 1.0〜2.0 倍に抑えた。

市区町村別の需要（1 月・季節係数 0.90）:

| 都市 | 人口 | Developed=0 | Developed=0.5 | Developed=1.0 |
|------|------|-------------|---------------|---------------|
| 宝塚 | 3 万 | 6 | 10 | 13 |
| 梅田 | 12 万 | 15 | 23 | 31 |
| 神戸 | 40 万 | 32 | 49 | 65 |

開発費（住宅・百貨店・遊園地）は Phase 1-8-2 の `BuildFacilityAction` で
実装する。開発度を上げるにはコストがかかるため、需要増と投資の
トレードオフが生まれる。Phase 1-8-2.5 では施設の基本コストを旧比 0.6 倍、
収入率を旧比 0.625 倍に調整し、開発効果と施設収入を抑えた
（`CONSTRUCTION.md` および `FacilityTable` 参照）。

### 需要の変動要因
- 人口（べき指数 0.6）
- 開発度（施設建設、1.0〜2.0 倍）
- 地価（高いと需要減）
- 競合路線
- 景気
- 季節

## 3. 運賃弾力性

```
需要変化 = 運賃変化 × 弾力性
弾力性 = -0.7（デフォルト）
```

| 弾力性 | 効果 |
|--------|------|
| -0.5 | 運賃上げても需要減りにくい |
| -1.0 | 標準 |
| -1.5 | 運賃に敏感 |

## 4. シェア争い

```go
func (g *Game) MarketShare(c *Company, line *Line) float64 {
    myScore := g.lineScore(line)
    totalScore := myScore
    for _, other := range g.competingLines(line) {
        totalScore += g.lineScore(other)
    }
    return myScore / totalScore
}

func (g *Game) lineScore(line *Line) float64 {
    score := 1.0
    score *= (1.0 / float64(line.Fare)) * 100  // 運賃が安いほど高い
    score *= float64(line.TrainsPerDay) / 10.0  // 本数
    score *= (1.0 + line.ElectrifiedBonus())     // 電化
    score *= (1.0 + line.SpeedBonus())           // 速度
    return score
}
```

## 5. 維持費

```go
func (g *Game) MaintenanceCost(line *Line) int64 {
    base := float64(line.LengthKm) * maintenancePerKm
    if line.Double {
        base *= 1.5
    }
    if line.Electrified {
        base *= 1.3
    }
    return int64(base)
}
```

| 係数 | 値 |
|------|-----|
| maintenancePerKm | 2800円/km/月（Phase 1-7.5 で 1000 → 20000、Phase 1-7.7 で 20000 → 2800。需要のべき乗則化で旅客収入が約 1/6 になったため、営業係数維持のためにスケール） |
| Double | ×1.5 |
| Electrified | ×1.3 |

## 6. 減価償却

- 路線: 50年定額
- 車両: 20年定額
- 施設: 30年定額

### 資産回転率（Phase 1-7.6）

建設費が過小だと投資回収が早すぎ、資金が雪だるま式に増える。Phase 1-7.6 で
`BaseCostPerKm` を 250000 円/km に引き上げ（`MECHANICS/CONSTRUCTION.md` 参照）、
梅田〜宝塚（19.1km）の建設費を約 477 万円（年間収入の約 0.9 倍、
投資回収約 6 年）とした。これにより 12 ヶ月の資金増加率は建設後資金比で
約 1.16 となり、Phase 1-7.5 の 1.85 倍から是正される。

### 目標の再定義（Phase 1-7.8）

Phase 1-7.7 の需要のべき乗則化により旅客収入が約 1/6 に減った一方で
`BaseCostPerKm` は据え置いたため、投資回収期間は梅田〜宝塚で約 22 年、
12 ヶ月の資金増加率は約 1.01〜1.03 となり、Phase 1-7.6 の目標
（投資回収 3〜7 年、資金増加率 1.05〜1.20）を満たさなくなった。

これは史実の戦前私鉄（投資回収 10〜20 年）に照らすとむしろ現実的である。
そこで Phase 1-7.8 で目標を次のように再定義した。開発度の効果を 1.0〜5.0 倍に
強化したことで、開発ありシナリオは目標を大きく上回る（投資回収が 1〜5 年に
短縮される）点に注意。

| シナリオ | 投資回収 | 資金増加率（建設後資金比） |
|---------|---------|--------------------------|
| 開発なし | 15〜25年 | 1.02〜1.10 |
| 開発あり（Developed 0.5） | 8〜15年 | 1.08〜1.20 |
| 開発あり（Developed 1.0） | 5〜10年 | 1.15〜1.30 |

根拠:
- 戦前の私鉄は投資回収 10〜20 年（史実）
- 沿線開発による需要増加で回収が早まる（小林一三モデル）

#### 実測値（Phase 1-7.8、梅田〜宝塚 19.1km・運賃 200 円・初期資金 900 万円）

| シナリオ | Developed | 営業係数 | 投資回収 | 資金増加率（初期比 / 建設後比） |
|---------|-----------|---------|---------|-------------------------------|
| 梅田〜宝塚（開発なし） | 0.0 | 80.9 | 22.0年 | 1.014 / 1.029 |
| 梅田〜宝塚（開発あり） | 0.5 | 25.4 | 2.3年 | 1.216 / 1.459 |
| 梅田〜宝塚（開発あり） | 1.0 | 15.1 | 1.2年 | 1.418 / 1.890 |
| 神戸〜梅田（競合あり） | 0.0 | 96.2 | — | — |
| 田舎路線（36.7km） | 0.0 | 167.9 | 赤字 | — |

開発なしは新目標（投資回収 15〜25 年、資金増加率 1.02〜1.10）を満たす。
開発ありは需要が 3〜5 倍になるため、営業係数・投資回収が劇的に改善する
（＝開発がゲームの核心）。開発コストは Phase 1-8-2 で実装する。

> 注: 旧 Phase 1-7.6 の目標（投資回収 3〜7 年）は、開発なしでは満たせない。
> 本フェーズで「史実準拠（戦前私鉄 10〜20 年）」に再定義した。

### 開発効果のバランス調整（Phase 1-8-2.5）

プレイテスト（1931 年・24 年プレイ）の結果、開発が強すぎることが判明した。

| 指標 | 旧（Phase 1-8-2） | 新（Phase 1-8-2.5） |
|------|-------------------|---------------------|
| DevelopedDemandFactor | 4.0 | 1.0 |
| 開発度 1.0 の需要倍率 | 5.0 倍 | 2.0 倍 |
| 営業係数（シナリオ別） | 14.3〜25.0 | 55〜90 を目標 |
| 24 年成長 | 62 倍 | 5〜10 倍 |
| 年率成長 | 19% | 8〜12% |

変更内容:
- `DevelopedDemandFactor` を 4.0 → 1.0（開発度 1.0 で需要 2.0 倍）
- `FacilityTable` の基本コストを旧比 0.6 倍、収入率を旧比 0.625 倍

#### 目標（営業係数・投資回収）

| シナリオ | 開発度 | 営業係数目標 | 投資回収目標 |
|---------|--------|-------------|-------------|
| 開発なし | 0.0 | 80〜90 | 15〜25年 |
| 開発 0.5 | 0.5 | 65〜80 | 10〜15年 |
| 開発 1.0 | 1.0 | 55〜70 | 8〜12年 |
| 競合あり | 1.0 | 70〜90 | — |

#### 実測値（Phase 1-8-2.5、梅田〜宝塚 19.1km・運賃 200 円）

| シナリオ | 開発度 | 営業係数 | 投資回収 | 資金増加率（24年） |
|---------|--------|---------|---------|-------------------|
| 梅田〜宝塚（開発なし） | 0.0 | 80.9 | 22.0年 | — |
| 梅田〜宝塚（開発あり） | 0.5 | 52.4 | 7.3年 | — |
| 梅田〜宝塚（開発あり） | 1.0 | 38.7 | 4.2年 | — |
| 神戸〜梅田（競合あり・等運賃 200 円） | 1.0 | 55.8 | — | — |
| 田舎路線（36.7km） | 0.0 | 167.9 | 赤字 | — |
| ネットワーク運用（7 都市・初期 9,000 万円） | — | — | — | **5.12 倍** |

> **仕様書との数値の相違（重要な注記）**: 仕様書の営業係数目標
> 「開発 1.0 → 55〜70」は、開発度 1.0 で需要を 2.0 倍にする本モデルでは
> 原理的に達成できない（55〜70 には需要倍率 概ね 1.2〜1.5 倍、すなわち
> `DevelopedDemandFactor` 約 0.35〜0.5 が必要）。本フェーズは仕様の指示
> どおり `DevelopedDemandFactor = 1.0` を優先し、実測値（38.7）に基づいて
> 検証する。開発による改善（営業係数 80.9 → 38.7、需要 2.0 倍）は阪急
> モデルの本質に一致する。競合あり・開発 1.0 は 55.8 となり、健全な私鉄の
> 範囲（55〜90）に収まる（仕様の 70〜90 には開発度 約 0.5 が必要）。
> 24 年成長は、cmd/play の世界（7 都市・初期 9,000 万円）でネットワークを
> 拡張した場合に 5.12 倍となり、目標 5〜10 倍を満たす。

## 8. 株価モデル

```go
func (g *Game) StockPrice(c *Company) int {
    // 純資産 + 収益期待 + 市場センチメント
    nav := c.NetAssets() / int64(c.TotalShares)
    earnings := c.AnnualProfit / int64(c.TotalShares)
    pe := g.marketPE()  // 市場のPER
    sentiment := g.marketSentiment()

    price := float64(nav)*0.5 + float64(earnings)*float64(pe)*0.5
    return int(price * sentiment)
}
```

## 9. 融資枠

```go
func (g *Game) CreditLine(c *Company) int64 {
    score := c.CreditScore()  // 0-100
    return int64(float64(c.NetAssets()) * float64(score) / 100.0)
}
```

信用スコア:
- 自己資本比率
- 収益性
- 株価
- 評判
- 政治圧力
