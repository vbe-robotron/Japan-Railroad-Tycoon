version: 1.0
updated: 2026-10-13

## 1. コンセプト

私鉄版HOI4。1880〜2020年の日本鉄道史を舞台に、
プレイヤーは鉄道会社を経営し、2020年に日本一の収益を目指す。

**キャッチコピー:** 路線を敷き、街を作り、ライバルを買収せよ。

## 3. ゲームの流れ

1. 会社を選ぶ（開始年は会社ごとに異なる）
2. 路線を敷設する
3. 街を開発する（百貨店・住宅・遊園地）
4. ライバルと競争・買収する
5. 2020年に最も収益の大きい会社を目指す

## 4. 勝利条件

**2020年12月時点で、日本で最も年間営業利益が大きい会社になる。**

- 指標: 年間営業利益 = 営業収益 − 営業費用
- 他社と比較して1位なら勝利
- ゲーム中も常にランキング表示

## 5. 敗北条件

| 条件 | 内容 |
|------|------|
| **買収される** | 他社に50%超の株を取得される |
| **経営破綻** | 資金枯渇 + 借金上限超過、または2年以上の連続赤字 |
| **民営化** | 国鉄操作時、累積赤字が閾値超過で1987年に分割民営化 |

## 6. ターン

- **1ターン = 1ヶ月**
- 1880〜2020年 = 約1,700ターン
- 全アクション実行後、`end-turn` で時間進行

## 7. コアメカニクス

### 7.1 路線敷設の4ゲート
詳細は `MECHANICS/CONSTRUCTION.md` 参照。

1. **技術ゲート**: 馬車鉄道（1880）、電気軌道（1895）、地下鉄（1925）等が解禁済み
2. **法規ゲート**: 私設鉄道条例（1887）、地方鉄道法（1919）等
3. **地形ゲート**: 平地1.0倍、丘陵1.5倍、山地3.0倍、市街地2.5倍
4. **経済ゲート**: 資金 ≥ 敷設コスト

### 7.2 収益モデル
詳細は `MECHANICS/ECONOMY.md` 参照。

```
収益 = 旅客収入 + 貨物収入 + 不動産収入 + 流通収入
     - 維持費 - 減価償却
旅客収入 = Σ(需要 × シェア × 運賃)
```

### 7.3 廃線の4ゲート
詳細は `MECHANICS/CONSTRUCTION.md` 参照。

1. **赤字継続**: 2年以上の連続赤字
2. **代替路線**: 他社路線 or バスあり
3. **政治圧力**: 自治体・住民の反対が閾値以下
4. **物理状態**: 老朽化 or 災害

### 7.4 M&A
詳細は `MECHANICS/MA.md` 参照。

- 株取得 → 50%超で子会社化
- TOB（敵対的買収）→ 防衛策あり
- 合併 → 有向グラフで統廃合を表現
- 阪急 + 阪神 → 阪急阪神HD のような史実統合

### 7.5 国鉄の特殊性
- 政治的に廃線しにくい
- 1968年以降に特定地方交通線を指定
- 1987年に累積赤字が閾値超え → 分割民営化
- プレイヤーが国鉄操作時は、ランダムでJR1社に割り当て

### 7.6 東京メトロの制約
- 2004年の営団→メトロ移行まで、街を作れない
- 代わりに地下鉄網の拡張と直通に注力

## 8. 最強キャラ（史実補正）

| 会社 | 特殊能力 | 効果 |
|------|---------|------|
| 阪急 | 小林一三 | **沿線開発力**、開発度の需要効果 1.0〜5.0 倍、不動産収入+50% |
| 東急 | 五島慶太 | 買収成功率+30%、買収コスト-20% |
| 営団/メトロ | 帝都高速度 | 都市部路線の需要+30%、街開発制約 |

### 阪急モデル（小林一三）と沿線開発力

阪急（箕面有馬電気軌道、1907年創業）の小林一三は「乗客を自ら作り出す」
思想のもと、鉄道事業と同時に沿線を開発した。史実の歩み:

- 1910年 箕面有馬電気軌道開業（梅田〜宝塚）
- 1910年代 沿線に住宅地を開発
- 1911年 宝塚新温泉開業
- 1914年 宝塚少女歌劇
- 1920年代 神戸線・京都線開業
- 1929年 阪急百貨店（梅田）

これにより阪急は沿線需要を 5 倍以上に伸ばした。

**ゲームでの表現（Phase 1-7.8）:**

```
需要 = (人口 / DemandBase)^0.6 × (1 + 開発度 × 4.0) × 季節係数
```

| 開発度 | 需要倍率 |
|--------|---------|
| 0.0 | 1.0 倍 |
| 0.5 | 3.0 倍 |
| 1.0 | 5.0 倍 |

- `City.Developed` を上げる施設: 住宅・百貨店・遊園地（Phase 1-8-2 の `BuildFacilityAction`）
- 開発度が高いと需要が最大 5.0 倍になり、営業係数・投資回収が劇的に改善する
- 阪急は開発が得意（特殊能力「沿線開発力」）
- 開発にはコストがかかるため、需要増と投資のトレードオフが生まれる

これにより「路線を敷くだけでなく、街を作ることがゲームの核心」となる。

## 9. 史実とフィクションのバランス

### 二層構造
```
┌─────────────────────────────────────┐
│  史実レイヤー（ハード制約）              │
│  技術・法規・地形・地価                 │
│  → 変えられない                        │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│  プレイヤーレイヤー（ソフト選択）         │
│  どこに・いつ・誰と敷くか               │
│  → 自由                                │
└─────────────────────────────────────┘
```

- 史実ルートは「AIのデフォルト行動」として実装
- プレイヤーは史実から外れてよい（ifルート）
- 各史実イベントには `conditions` を設定し、プレイヤーが外れると発動しない

### 難易度
| 難易度 | 史実 | フィクション |
|--------|------|-------------|
| easy | 5 | 5 |
| normal | 7 | 3 |
| hard | 9 | 1 |
| ironman | 10 | 0 |

## 12. 拡張性

- すべてのデータをJSONコンフィグで差し替え可能
- Modで駅・会社・イベントを追加可能
- スキーマバージョン管理
- 静的データ（Node/City/Company/Event）は意味的ID
- 動的データ（Line/Facility/Game/EventLog）はNanoID
